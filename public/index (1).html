Where should you begin?

New to computers

Start at Phase 0 and work up. Skipping the foundations is the most common reason people get stuck later.

Know the basics

Jump into guided labs, then come back and fill gaps as they show up.

Ready to specialize

Pick a path: Red Team, Blue Team, Cloud Security or Digital Forensics. You can switch any time.

What you will be able to do

  • Explain how computers, networks and operating systems fit together.
  • Work comfortably in Linux and understand Windows and Active Directory.
  • Write small scripts to automate boring work.
  • Practice safely and legally, and document what you did in a real report.
  • Build a portfolio you can show to someone hiring.

Common questions

Do I need to know how to code first?

No. Programming arrives in Phase 4, after the concepts that make it useful.

How long does this take?

Roughly six to twelve months at a few hours a week, depending on your starting point. Consistency beats speed.

Is it legal to practice?

Yes, on systems you own or platforms built for it. Read the Rules tab before you touch anything.

Where is my progress stored?

In this browser, per profile. Use Export Progress on the Profile page to keep a copy.

PHASE 0 — Computer Fundamentals

~2–4 weeks

Goal: understand what a computer actually does.

Hardware: CPU, RAM, storage, motherboard, GPU, peripherals
Binary, hexadecimal, bits/bytes, files and processes
Operating systems, kernels, applications, drivers
Filesystems, permissions, users and processes
Virtualization and virtual machines

Checkpoint: explain what happens from pressing a power button to opening a web page.

PHASE 1 — Networking

~3–6 weeks

Goal: understand how machines communicate.

OSI and TCP/IP models
Ethernet, MAC addresses, ARP
IPv4/IPv6, subnetting, CIDR
TCP vs UDP, ports and sockets
DNS, DHCP, HTTP/HTTPS, TLS
NAT, routing, firewalls, VPN concepts
Read packet captures in Wireshark

Checkpoint: capture a DNS + HTTP/HTTPS conversation in your own lab and explain each major packet.

PHASE 2 — Linux

~3–5 weeks

Goal: become comfortable living in a terminal.

Navigation, files, pipes, redirects and text processing
Users, groups, permissions and sudo
Processes, services, logs and package management
SSH and basic networking commands
Bash scripting fundamentals
Complete OverTheWire Bandit

Checkpoint: set up a Linux VM and administer it from the command line without relying on a GUI.

PHASE 3 — Windows + Active Directory

~3–6 weeks

Goal: understand the dominant enterprise endpoint environment.

Windows architecture, users, groups and permissions
PowerShell basics
Event Viewer, Windows logs and Defender concepts
Services, scheduled tasks and registry basics
Active Directory: domain, DC, OU, GPO, Kerberos, LDAP

Checkpoint: explain how a domain login works and where an administrator would investigate suspicious activity.

PHASE 4 — Programming + Automation

~4–8 weeks

Goal: write small programs instead of depending on someone else's tool.

Python syntax, variables, functions, loops and data structures
Files, JSON, exceptions and modules
HTTP requests and APIs
Regular expressions and parsing
Git: clone, branch, commit, diff, merge and push
Build 3 small security-related utilities for your own lab

Checkpoint: read unfamiliar Python and modify it safely.

PHASE 5 — Security Fundamentals

~3–5 weeks

Goal: learn the language and models used across security.

CIA triad, assets, threats, vulnerabilities and risk
Authentication vs authorization
Least privilege, defense in depth, zero trust
Hashing, encryption, digital signatures and PKI
Vulnerability management and patching
Logging, monitoring, detection and incident response
Read NIST CSF 2.0 at a high level

PHASE 6 — Hands-on Cybersecurity

~6–10 weeks

Goal: connect theory to controlled practice.

Complete TryHackMe Pre Security
Complete TryHackMe Cyber Security 101
Learn Nmap concepts in authorized labs
Learn Wireshark packet analysis
Learn basic vulnerability assessment
Learn web security fundamentals with PortSwigger labs
Write a report for every substantial lab

Tools

The programs practitioners use, with a link to each project's official site.

Read before you install. Many of these tools are dual-use, meaning they help defenders and attackers alike. Run them only against systems you own or have written permission to test, and preferably inside an isolated virtual machine. Download from the official site only, verify checksums or signatures when offered, and never run tools from unknown sources on your main computer.

Rules and safety standards

These skills are powerful. Use them only where you have permission, and leave every system as you found it.

Ask these three questions before every action
  1. Do I own this system, or do I have written permission to test it?
  2. Is this exact action inside the agreed scope and time window?
  3. Could it expose data or interrupt a service?

If any answer is no or unclear, stop and get the scope confirmed first.

Permission

  • Public is not permission. A reachable website is not an invitation to test it.
  • Get scope in writing: targets, methods, dates, and who to contact.
  • Follow each platform's rules, including CTFs and bug bounties.

Data

  • Never use credentials that are not yours.
  • Do not copy, keep or publish private data you come across.
  • Treat sensitive data in a lab as real and follow the lab's rules.

Impact

  • Use the least disruptive method that answers the question.
  • Avoid actions that delete data, lock accounts or flood a service.
  • Do not bypass a safety control just to see if it works.

Practice

  • Prefer CTFs, training platforms and VMs you own.
  • Keep notes: commands, observations and results.
  • For every attack you study, learn how it is detected and fixed.

If something goes wrong

  1. Stop. Do not try to undo it with more testing.
  2. Write down what you did, when, and what you saw.
  3. Tell the lab owner or the contact in your scope document.
  4. Follow their reporting process and share only safe evidence.

Computer misuse laws, such as the CFAA in the United States and the Computer Misuse Act in the UK, apply even when you mean well. This page is guidance for learners, not legal advice.
